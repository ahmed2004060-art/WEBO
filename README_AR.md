# WEBO Lab — مشروع Android مستقل

## هوية التطبيق
- اسم التطبيق: WEBO Lab
- `applicationId`: `com.webo.lab`
- `namespace`: `com.webo.lab`
- `minSdk`: 24
- `targetSdk`: 34
- أول `versionCode`: 200 محلياً؛ يزيد تلقائياً مع رقم تشغيل GitHub Actions.
- التوقيع: مفتاح جديد مستقل باسم `webo_lab`، لا يستخدم مفتاح التطبيق الأصلي.

## مصدر الوظائف
هذا المشروع أُنشئ من ملف المصدر الأصلي `webo_app_pro_fixed-24.zip`.
نُقلت ملفات Kotlin الأساسية السبعة إلى مساحة الحزمة الجديدة مع الاحتفاظ بوظائفها: المتصفح، التبويبات، الصفحة الرئيسية، التنزيلات، التقاط الوسائط، HLS/DASH، المشغّل، DRM الرسمي، التخزين، السجل، المفضلة، الإعدادات، وفحص الواجهة الشامل.
نُقلت موارد التطبيق الأصلية الـ49 دون تغيير بايت واحد. الإضافة المرئية داخل واجهة WEBO هي بطاقة فتح مختبر الاختبار، بينما بقيت الألوان والأيقونات والصفحات والتبويبات الأصلية كما هي.

## مختبر الاختبار المدمج
يفتح من أدوات التطبيق باسم «مختبر الاختبار الآلي». عند فتحه للمرة الأولى يبدأ الاختبارات المحلية تلقائياً، ثم يختبر تفاعل صفحات WebView، وتشغيل MP4 وHLS وDASH عبر Media3، ثم يشغّل فحص واجهة WEBO الأصلي باستخدام المواقع المحلية. بعد نجاح فحص الواجهة يطلب إعادة تشغيل العملية والعودة إلى المختبر. يمكن استخدام الأوامر يدوياً أيضاً.

إعادة تشغيل العملية باستخدام AlarmManager محاولة فعلية من داخل التطبيق، لكن Android قد يؤجل أو يمنع فتح Activity من الخلفية وفق إصدار النظام وسياساته؛ لذلك تُسجل نتيجة المحاولة ولا تُعد ضماناً على كل الأجهزة. لا يُستخدم ADB في التشغيل المعتاد للمختبر.

## الوظائف الاختبارية
- خادم HTTP محلي على `127.0.0.1` بمنفذ عشوائي لا يستقبل اتصالات من الشبكة الخارجية.
- مواقع محلية للأخبار والمتجر والتواصل والقراءة والمعرض والتنزيل والفيديو.
- صور JPG/PNG وفيديوهات MP4 صغيرة.
- قائمة HLS وثلاثة مقاطع MPEG-TS.
- قائمة DASH بخمسة مقاطع fMP4 ومقطع سادس متتابع لتغطية طلب المشغلات المسبق عند حد نهاية القائمة.
- نقاط اختبار HTTP 200/302/404/500، النطاقات الجزئية، والمهل البطيئة.
- اختبارات قراءة/كتابة التخزين، قاعدة بيانات السجل، ذاكرة أيقونات المواقع، وMedia3 لتشغيل MP4/HLS/DASH.
- فحص واجهة WEBO الشامل الأصلي، موصول بالمواقع المحلية بدلاً من مواقع الإنترنت أثناء تشغيله من المختبر.
- اختبار تفاعل DOM فعلي داخل WebView: زر إضافة المنتج إلى السلة وحقل/زر نشر المنشور.
- سجل SQLite محلي يربط الوقت ومعرف العملية والمكوّن والوظيفة والنتيجة والمدة وتفاصيل الاستثناء.
- تقرير ZIP يحوي `events.csv` و`environment.txt` وسجل `full_ui_scan.txt` إذا كان متاحاً.

## تحسين أيقونات المواقع
تُخزّن أيقونات المواقع في `filesDir/site_icons` مع ذاكرة RAM، ويُمنع تكرار طلب الأيقونة الموجودة. تُتجنب إعادة المحاولة للمواقع التي فشل تحميل أيقونتها لمدة سبعة أيام، وتُحذف مدخلات الكاش التالفة لإعادة المحاولة. الحد الأقصى للكاش الدائم 4 MiB.

## البناء المحلي
يتطلب Android SDK وJDK 17 وGradle 8.7 أو أحدث متوافقاً مع AGP 8.5.2.

من مجلد المشروع:

```bash
gradle :app:assembleRelease --no-daemon
```

ينتج APK في:
`app/build/outputs/apk/release/app-release.apk`

## تحديثات التطبيق الجديد
احتفظ دائماً بالملفين التاليين في مكان خاص وآمن:
- `app/webo_lab.keystore`
- `webo-lab-signing.properties`

لا تنشئ مفتاحاً جديداً بين تحديثات WEBO Lab. يجب أن يبقى `applicationId` هو `com.webo.lab`، وأن يزيد `versionCode` في كل إصدار حتى يُقبل كتحديث فوق الإصدار السابق. يمكن تعيين `WEBO_LAB_BUILD_NUMBER` للبناء المحلي؛ أما GitHub Actions فتستخدم رقم تشغيلها تلقائياً. فقدان المفتاح يعني عدم إمكانية تحديث النسخ المثبتة الموقعة به بالطريقة المعتادة.

## بناء GitHub Actions
ملفات التوقيع مستثناة من Git عبر `.gitignore`. لإعداد بناء آلي موقّع، أضف هذه المستودعية كـ GitHub Actions Secrets:
- `WEBO_LAB_KEYSTORE_BASE64`: محتوى `base64 app/webo_lab.keystore` بعد حذف فواصل الأسطر.
- `WEBO_LAB_STORE_PASSWORD`: كلمة مرور المخزن.
- `WEBO_LAB_KEY_ALIAS`: `webo_lab`.
- `WEBO_LAB_KEY_PASSWORD`: كلمة مرور المفتاح.

في Termux/Linux يمكن توليد قيمة السر الأول هكذا:

```bash
base64 app/webo_lab.keystore | tr -d '\n'
```

تشغّل Actions مهمة `assembleRelease` وتنتج APK موقّعاً بالمفتاح نفسه.

## حدود التحقق الحالية
- تم فحص سلامة ZIP والموارد وملفات XML.
- اجتاز خادم المواقع الوهمية واختباراته المستقلة اختبارات HTTP والمواقع والصور وMP4 وHLS وDASH والتنزيل والتخزين والكاش. شُغّل كذلك تجميع Kotlin محدود بخلفيات Android بديلة لوحدتي الخادم ومشغّل الاختبارات، واجتازت الاختبارات الثمانية في بيئة JVM المحلية.
- تحققت أدوات `ffprobe` و`ffmpeg` من ملفات MP4 وHLS وDASH التجريبية؛ DASH يتضمن مقطعاً احتياطياً لتجنب خطأ طلب المقطع التالي عند نهاية نافذة التشغيل.
- لم يتم بناء APK أو اختباره على جهاز Android في بيئة إعداد الحزمة هذه، لعدم توفر Android SDK وGradle. لم يُتحقق داخل جهاز Android من تجميع جميع Activities أو من سلوك Media3 وWebView الفعلي؛ اختبارات FFmpeg تتحقق من سلامة ملفات الوسائط نفسها فقط. يجب تنفيذ البناء والتشغيل الأول على Android SDK/CI قبل اعتماد النسخة كتطبيق إصدار نهائي.
